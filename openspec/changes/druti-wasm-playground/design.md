## Context

- The Cargo workspace has `crates/bengali-ime-core`, which holds the engine, composer, transpile and data
  tables, and `crates/bengali-ime-ffi`, the UniFFI surface. The FFI crate's `[lib] name` is
  `bengali_ime_ffi`. That name ends up in `libbengali_ime_ffi.a`, in the generated Swift module and in
  the `BengaliIMEFFI.xcframework` layout that `macos/` and CI check.
- `fixtures/engine/*.json` are generated by `scripts/gen-fixtures.ts` from the TypeScript engine in
  `src/`. `fixtures/composer/*.json` are written by hand. Only the core crate's `tests/parity.rs` and
  `tests/composer.rs` read them, through `CARGO_MANIFEST_DIR/../../fixtures`.
- The playground (`examples/playground/`) is a Vite app that uses the root `package.json` (yarn 1) and
  imports the TypeScript `BengaliIME` through a Vite alias. It uses a `<textarea>` and applies
  `IMEAction`s directly.
- The composer (`Composer::key/backspace/flush/reset`) returns `Update { replace_before, commit, pending,
  handled }` with UTF-16 counts. Engine English mode exists, but the composer doesn't expose it, because
  on macOS you switch input sources instead.
- The release workflow runs `make -C macos dmg` and uploads the DMG and its `.sha256` to a draft release.
  The built app is at `macos/build/DerivedData/Build/Products/Release/Druti.app`.
- Neither `wasm-pack` nor the `wasm32-unknown-unknown` target is installed on the author's Mac yet.

## Goals / Non-Goals

**Goals:**
- One engine (Rust) for macOS and the web. The playground behaves like the macOS input source, keystroke for keystroke.
- No change to the macOS build output: same Swift module names, same bundle, same XCFramework layout.
- The playground is a static site that can be built from a clean checkout with `rustup`, `wasm-pack` and `node`.

**Non-Goals:**
- Publishing `druti-wasm` to npm. The package API is shaped for it, but publishing needs a separate change.
- Mobile browsers' virtual keyboards. They send `Unidentified` keys or IME composition events. The playground
  targets hardware keyboards and falls back to normal browser input for keys it can't read.
- Renaming Swift or Xcode identifiers, or the FFI library name.
- Notarization or Developer ID signing.

## Decisions

### D1. Rename the crate packages and directories, keep the FFI library name
`git mv crates/bengali-ime-core crates/druti-core` and do the same for `ffi`. The package names become
`druti-core` and `druti-ffi`, so Rust code imports `druti_core`. In `druti-ffi/Cargo.toml`, `[lib] name`
stays `"bengali_ime_ffi"`, so `libbengali_ime_ffi.a`, the UniFFI namespace, the generated Swift module and
the CI `lipo` checks don't change. `scripts/build-xcframework.sh` (`--package druti-ffi`) and
`macos/Makefile` (the cargo-about manifest path) are updated to match.
- *Alternative:* keep the directories and rename only the packages. Rejected because directory names that
  don't match package names confuse `cargo -p`.

### D2. Fixtures move into the core crate as golden data
`git mv fixtures crates/druti-core/tests/fixtures` (engine and composer, plus the README, rewritten to say
the files are golden, edited by hand or with a one-off script, and never regenerated). The tests read
`CARGO_MANIFEST_DIR/tests/fixtures`. `tests/parity.rs` becomes `tests/fixtures.rs`. Its assertions and
the fixture contents don't change, so the Rust results before and after the move are identical. The
error hint `run yarn fixtures` is removed.
- *Alternative:* a Rust fixture generator. Rejected because the author chose frozen golden data, and a
  generator fed by the engine it tests can't catch regressions.

### D3. `druti-wasm`: wasm-bindgen classes without serde
`crates/druti-wasm` has `crate-type = ["cdylib", "rlib"]` and depends on `druti-core` and
`wasm-bindgen` (pinned to an exact version, as UniFFI is). It exports:
- `Config`: a `#[wasm_bindgen]` struct with public `bool` fields `bengaliDigits`, `dariForPeriod` and
  `smartQuotes` (`js_name`), and a constructor that returns the defaults.
- `Update`: `#[wasm_bindgen(getter_with_clone)]` with `replaceBefore: number`, `commit`, `pending` and `handled`.
- `Composer`: `new Composer(config?)`, `key(key, textBeforeCaret?)`, `backspace()`, `flush()`,
  `reset(textBeforeCaret?)`, a `pending` getter, a `config` getter and `setConfig(config)`.
- `transpileRomanDocument(document, preserveLineBreaks, config?)`.

wasm-bindgen produces the `.d.ts`, so the playground's TypeScript is type-checked against the real API.
Using plain classes avoids adding `serde`, `serde-wasm-bindgen` and `tsify`, and the objects are tiny.
- *Alternative:* serde objects. Rejected because they need extra dependencies and the typings are
  `any` unless `tsify` is added too.
- Panics: on `wasm32-unknown-unknown` a panic traps and `catch_unwind` doesn't help. The playground
  wraps every call, and on an exception it logs the error, recreates the composer, and lets the key through
  as normal browser input. This mirrors the FFI crate's "typing never stops" rule.

### D4. Build with `wasm-pack --target web` into the playground
`examples/playground/package.json` has a script
`wasm: wasm-pack build ../../crates/druti-wasm --target web --out-dir ../../examples/playground/wasm --no-pack`,
and `dev`/`build` run it first. `--target web` emits an ES module plus a `.wasm` file loaded through
`new URL(..., import.meta.url)`. Vite handles that without plugins in both dev and build. The `wasm/`
output is gitignored. `vite.config.ts` sets `base: './'` so the build works under the Pages subpath `/druti-ime/`.
- *Alternative:* `--target bundler` + `vite-plugin-wasm`. Rejected because it adds plugins for no gain.
- *Alternative:* `cargo build` + `wasm-bindgen-cli`. Rejected because the CLI version must match the crate
  version exactly, which wasm-pack takes care of.

### D5. The editor is a model-backed `contenteditable`
The editor is a `<div contenteditable="plaintext-only">` (with a fallback to `contenteditable="true"`
where unsupported), backed by a small model: `text` (committed document), `caret` (UTF-16 offset in
`text`) and `pending`. The editor renders it as a text node, `<span class="pending">` (underlined) and a
text node, with the caret placed after the pending span.

On `keydown`:
- If the key is `Backspace`, send `backspace()`. If it's `Enter` or a single printable character with no
  Ctrl, Meta or Alt, send `key(key, text.slice(0, caret))` in Bengali mode.
- Apply the update: remove `replaceBefore` units before `caret` from `text`, insert `commit` at `caret`,
  advance `caret` and set `pending`. If `handled`, `preventDefault()`. Otherwise the browser does what it
  normally does with the key after the model is written back to the DOM (for example, backspace with no
  pending text deletes a character).
- Any other key (arrows, Tab, shortcuts) first flushes, which commits the pending text, and then lets the browser act.

On `selectionchange` caused by the mouse, `paste`, `cut`, `drop`, `blur` or any `input` event not
produced by the model, the playground commits the pending text, re-reads `text` and `caret` from the DOM
and calls `reset()`. This is the same "caret moved: reset" rule the macOS app follows.
- *Alternative:* a textarea with a floating pending badge. Rejected because the author chose inline underline.

### D6. English mode lives in the playground
The toggle calls `flush()` when English mode is turned on and `reset(textBeforeCaret)` when it's turned off. While it's on,
keydown does nothing and the browser types normally. The engine's own English mode is not exposed. That matches
macOS, where the user switches input source, and keeps the WASM API the same shape as the FFI API.

### D7. Playground layout
```
examples/playground/
  package.json      private "druti-playground", yarn 1, vite + typescript only
  tsconfig.json     strict, bundler resolution, includes src/ and wasm/*.d.ts
  vite.config.ts    base './', server.fs.allow includes the wasm/ output
  index.html        header (title, DMG link), editor panel, settings, bulk panel
  src/main.ts       wiring, settings, English toggle, bulk panel
  src/editor.ts     D5 model and DOM rendering
  src/styles.css
```
The root `package.json`, `tsconfig*.json`, `vite.config.ts`, `vitest.config.ts`, `yarn.lock`,
`.npmignore` and `node_modules/` are removed. The repo root is a pure Cargo workspace plus `macos/` and `examples/`.

### D8. CI and Pages
- `ci.yml`: the `test` job (Node, Vitest, fixture freshness) becomes a `web` job. It installs Rust with the
  `wasm32-unknown-unknown` target and wasm-pack (`taiki-e/install-action`), runs `cargo build -p druti-wasm --target wasm32-unknown-unknown`,
  then `yarn --frozen-lockfile` and `yarn build` in `examples/playground`. The `rust` job is unchanged,
  except that `cargo test --all` now also covers `druti-wasm`'s host-side unit tests. Clippy runs for
  the workspace on the host target. `druti-wasm` compiles on the host because wasm-bindgen stubs are fine there.
- `pages.yml`: triggered on push to `main` and `workflow_dispatch`, with `permissions: pages: write,
  id-token: write` and `concurrency: pages`. It does the same build steps, then
  `actions/upload-pages-artifact` (path `examples/playground/dist`) and `actions/deploy-pages`.
  It needs Pages enabled with "GitHub Actions" as the source. The maintainer does this once, and the
  first deploy fails with a clear error until it's done.

### D9. The release attaches a zipped app
`macos/Makefile` gets an `app-zip` target that runs
`ditto -c -k --keepParent "$(APP)" build/Druti-$(VERSION).app.zip` on the same `$(APP)` that `dmg`
packs. `ditto` keeps the ad-hoc signature, extended attributes and symlinks, which `zip -r` can break.
`release-macos.yml` runs `make dmg app-zip`, checksums both files and uploads all four assets. The release
notes template gets a "Prefer a zip?" line and a playground link, and all its URLs change to `druti-ime`.
A zip downloaded in a browser carries the quarantine flag. After it's unzipped, opening the app goes through
the same Open Anyway step and installer mode (`Installer.swift` removes the quarantine flag from the installed
copy), so no Swift code changes.

### D10. Repository and local folder rename
The GitHub repo is already `ahamed/druti-ime` (the old URL redirects), and the local `origin` has been
switched. Every hard-coded URL in the repo changes to `druti-ime`. The local folder
`~/development/pet/bengali-ime` is renamed to `druti-ime` after the release is tagged. That happens outside
the repo and isn't a task here.

## Risks / Trade-offs

- [Golden fixtures can be edited carelessly] → The fixtures README explains that edits go in the same
  commit as the engine change. Reviews see fixture diffs next to the engine diff.
- [`contenteditable` differs between browsers (caret placement, `plaintext-only` support)] → Keep the DOM
  flat (at most three nodes). Place the caret explicitly after every render. Test manually in Safari,
  Chrome and Firefox (task 4.5).
- [A WASM trap in the browser] → D3: wrap every call and recreate the composer.
- [The first Pages deploy fails because Pages isn't enabled] → A one-time maintainer step, listed in
  tasks. The build job in `ci.yml` still guards pull requests.
- [The wasm-pack install slows CI] → Use prebuilt binaries through `taiki-e/install-action`, and rust-cache.
- [Removing TypeScript removes the "reference" that caught Rust bugs] → Accepted by the author. The Rust
  suite already replays every case the TypeScript tests had, and those files are kept.

## Migration Plan

1. Land this change as one PR from `druti-wasm-playground`, with CI green.
2. Enable GitHub Pages (source: GitHub Actions) once the maintainer approves. Re-run the Pages workflow.
3. Tag `macos-v1.0.0` on `main`. The workflow creates the draft release with the four assets.
4. The maintainer runs the carried-over Mac checks (task group 7) against the draft assets, then publishes.

Rollback: revert the PR. The macOS build doesn't depend on the web pieces, and the fixtures are only moved.
