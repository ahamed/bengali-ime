## Why

Backspace in Druti doesn't match what a Bengali typist expects. In pending text it removes a whole
grapheme cluster, so `dm` (`দ্ম`) disappears in one press instead of going back to `দ`. On committed
text the host deletes one code point, which leaves a dangling hasant (`দ্ম` → `দ্`). The engine's own
Backspace undoes keystrokes, so an invisible silent `o` uses up a press. And once the caret moves,
the next consonant can never continue the cluster before it: with the caret after `ত` in `করত`, `h`
gives `তহ` instead of `থ`.

## What Changes

- **BREAKING (behaviour): Backspace removes one letter.** A letter is:
  - a consonant together with the hasant joining it to the consonant before, plus its nukta if
    decomposed;
  - otherwise, a single kar, sign, independent vowel, digit or punctuation mark.

  No hasant is ever left dangling: `দ্ম` → `দ`, `ন্ত্র` → `ন্ত` → `ন`, `খ` → nothing, and
  `করতে` → `করত` → `কর` → `ক`. Text that isn't Bengali loses one extended grapheme cluster. Only
  visible text counts, so keystrokes that produced nothing (the silent `o`) never use up a press.
- **BREAKING (behaviour): the engine's Backspace uses the same rule.** `Engine::process_backspace`
  stops undoing keystrokes (`kh` then Backspace now leaves nothing, not `ক`). The undo history is
  removed, and the affected engine fixtures are regenerated.
- **The remainder stays live.** After a Backspace, the consonant run left before the caret becomes
  the cluster again, so `dm`, Backspace, `h` gives `ধ` and `করতে`, Backspace, `h` gives `করথ`.
- **The cluster before the caret resumes.** After a reset (the caret moved or was clicked, typing
  started, or the document changed underneath), the trailing consonant run of the text before the
  caret becomes the cluster: caret after `ত` + `h` gives `থ`, after `দ` + `m` gives `দ্ম`. The
  run is consonants joined by hasants, with nukta; it stops at a kar, vowel, `ং ঃ ঁ ৎ`, space or
  punctuation. Clusters the engine ended itself (silent `o`, space, a kar) stay ended, so `kom`
  still gives `কম`. Resumed text stays plain until the next key rewrites it through
  `replace_before`.
- **Backspace on committed text.** `Composer::backspace` takes an optional text-before-caret (a
  UniFFI default of `None`; optional in WASM). With it, and with that text ending in a Bengali letter,
  Druti deletes the letter itself through `replace_before`. Without it, the host deletes as it does
  today.
- **`key_reads_document` is true for consonant keys too**, so hosts supply context for them and
  resuming works in the Mac app without Swift changes.
- **The playground** passes the text before the caret to Backspace.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `rust-engine-core`: "Keystroke-undo backspace" becomes letter backspace. A new requirement covers
  resuming the cluster from the output.
- `ime-composer`: "Grapheme backspace in pending text" becomes letter backspace, for pending text
  and, given context, committed text. A new requirement covers resuming the cluster before the caret
  after a reset or a Backspace. The "never rewritten" requirement gains that exception, and more keys
  read the document.
- `web-playground`: the editor passes the text before the caret to Backspace, and a click after a
  consonant resumes its cluster.

## Impact

- **`crates/druti-core`**:
  - `engine.rs`: letter deletion, resuming the cluster, and removing `UndoEntry`, the undo stack and
    the snapshot constants.
  - `composer.rs`: `backspace(text_before_caret)`, the resume flag, pulling a resumed prefix into
    pending, and `key_reads_document`.
  - A new private `letters` module.
  - Public API: `Composer::backspace` gains a parameter, and `Engine::resume_cluster` is added.
- **Fixtures**:
  - `engine/random.json`: every case with a Backspace step is regenerated by a one-off script.
  - `engine/unit.json`: the 3 Backspace scenarios.
  - `composer/backspace.json` and `composer/context.json`: rewritten and extended, with the test
    harness learning `ctx` on Backspace steps.
- **Bindings**:
  - `druti-ffi`: `backspace(text_before_caret: Option<String> = None)`. Hand-written Swift is
    untouched and still compiles, because the generated bindings aren't committed.
  - `druti-wasm`: `backspace(textBeforeCaret?)`.
  - Both parity tests are updated.
- **Playground**: `examples/playground/src/editor.ts` passes the context to Backspace.
- **macOS app**: no Swift app code changes; one Swift test assertion is flipped, because `k` now reads the document. It picks up letter backspace in pending text and cluster resuming
  wherever the app exposes its text. Backspace on committed text stays host-handled on the Mac until a
  separate follow-up change passes context from Swift.
- **Docs**: the "How typing works" section of `README.md` and the fixtures README (the meaning of `bs`).
