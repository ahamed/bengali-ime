# Proposal

## Why

The bengali-ime algorithm only runs inside web editors today, so it can't be used as the everyday
Bangla keyboard on a Mac. A native macOS input source built on the same algorithm lets the author
type deterministic phonetic Bangla in every app. It also shows the exact Bengali on every keystroke,
with no suggestion list and no guessing.

## What Changes

- Add a **Rust port of the engine** (`crates/bengali-ime-core`) that reproduces the TypeScript
  `BengaliIME`, its Akkhar rules, its data tables and `transpileRomanDocument` exactly.
  The TS library stays the reference implementation.
- Add **parity fixtures** (`fixtures/engine/*.json`) generated by the TS engine, and a generator
  script. `cargo test` replays them, and CI fails when either engine drifts from the committed fixtures.
- Add a **composer** layer in Rust that turns engine actions into a commit/pending split for
  marked-text hosts. It adds grapheme-cluster Backspace within the pending text, holds a lone `-` so
  `--` → `—` works, and offers optional toggles (Bengali digits, দাঁড়ি for `.`, smart quotes) that
  default to TS-identical behaviour.
- Add **UniFFI bindings** (`crates/bengali-ime-ffi`) and a script that packages the core as an
  XCFramework for arm64 macOS. Nothing macOS-specific goes into the core or the FFI crate, so an
  iOS keyboard extension can reuse them later.
- Add a **macOS input source** (`macos/`, Swift + AppKit + InputMethodKit, XcodeGen project) named
  *Bangla Phonetic*. It includes key routing, marked text with the underline hidden, reading the
  text before the caret, reset when the caret moves, an input menu with toggles and
  "Convert selection", and `make install` / `make uninstall` for local ad-hoc-signed installs.
- Extend **CI** with a Rust job (fixtures, tests) on Linux and a macOS job that builds the
  XCFramework and the input method app.
- No change to the TS engine's observable behaviour. No breaking changes to `@ahamed/bengali-ime`.

## Capabilities

### New Capabilities
- `rust-engine-core`: Rust engine with the same per-keystroke behaviour as the TS `BengaliIME`
  (actions, `output`, `buffer`), bulk transpilation, and the fixture-based parity contract with the
  TS engine.
- `ime-composer`: Host adapter that turns engine state into committed text plus pending (marked)
  text, with grapheme Backspace, dash holding, context fallback, reset and optional output toggles.
- `macos-input-source`: The InputMethodKit input source: registration and install, key routing,
  marked-text presentation, reading document context, input menu toggles, Convert selection.

## Impact

- **New code:** `Cargo.toml` (workspace), `crates/bengali-ime-core`, `crates/bengali-ime-ffi`,
  `fixtures/`, `scripts/gen-fixtures.ts`, `scripts/build-xcframework.sh`, `macos/` (Swift sources,
  `project.yml`, `Info.plist`, icon, `Makefile`).
- **Existing code:** `src/` is unchanged. `package.json` gets a `fixtures` script, and
  `.github/workflows/ci.yml` gets the Rust and macOS jobs. `docs/macos-input-source.md` is
  corrected where it disagrees with the design artifact.
- **New dependencies:** Rust `unicode-segmentation` and `uniffi`; build tools `xcodegen` (Homebrew)
  and Xcode on the Mac. No new runtime dependencies for the npm package.
- **Environments:** Rust and fixture work can be done and verified on Linux. The XCFramework, the
  input method and the app compatibility checks need the author's Apple Silicon Mac (macOS 14+).
- **Distribution:** personal use only. Ad-hoc signed, no notarization, no paid Apple Developer account.
